Derivation rules:

- `overall.level`: `"down"` when `health.process.status === "failed"`; `"ok"` when read is `ok` **and**

- `overall.reasons` is the concatenation of the three health reason arrays mapped through

  `deno task check` fails if a reason is added upstream without a human sentence.

- `priority` is **positional**: `index + 1`.
- `writable` is `cacheIdentity(publication) === inputs.writableIdentity`, and must be `false` for every
  cache when `writableIdentity` is `undefined`.
- `updatedAt` derives from `event.created_at`; `expiresAt` from `publication.expiresAt`, compared
  against the injected `now` for an `expired` flag.
- `nhash` is emitted only when it matches
  `/^nhash1[023456789acdefghjklmnpqrstuvwxyz]{6,120}$/`, otherwise the empty string. Do **not** reuse
  `safeHtreeLink` — it demands an `htree://` prefix that `root.nhash` does not carry
  (`src/protocol/nhash.ts:17-21`).
- `blossomServers` entries pass through the newly exported `safeEndpoint`, dropping any that return

- `setup.substituter` normalizes wildcard binds so the snippet is pasteable: `0.0.0.0` → `127.0.0.1`,

  through `new URL()` and emit `url.origin`.
- `setup.trustedPublicKeys` is `nixSigKeys.map((k) => `${k.name}:${k.encoded}`)` across all caches,
  deduped and sorted. `encoded` is already regex-validated at `src/protocol/publication.ts:100`;
  `name` is **not** validated for HTML safety, so the renderer must escape it.
- `storage.usedPercent` is `capacityBytes > 0 ? clamp(round(readyBytes / capacityBytes * 100), 0, 100) : 0`.
  When `inputs.storage` is absent, emit `available: false` with zeroed numbers.
- `write.signerDetail` is a truncated `signerPubkey` (first 6 hex characters plus an ellipsis) or the
  empty string. Never emit the full pubkey's surrounding context, and never emit any signer secret.
- `write.publication` is present only when `batchId` is defined: `{ batchId, replicas, relays }` where
  each is an `EndpointProgress` from `summarizeEndpointWork`.

`summarizeEndpointWork(work: readonly EndpointWork[], kind: "replica" | "relay"): EndpointProgress`

status !== "complete"`; `retries` = `sum(max(0, attempts - 1))`; `exhausted` = `status === "exhausted"`.
It receives rows **already filtered to one batch** — batch filtering stays with the caller.

**2a. Create `src/operations/status_page.ts`.**

Exports `escapeHtml(value: string): string`, `formatBytes(value: number): string`, and
`renderStatusPage(snapshot: StatusSnapshot): string`. It imports only the `StatusSnapshot` type. It is
a **total function of its argument** — no `Date.now()`, no `Deno.*`, no configuration. The same
snapshot in must produce a byte-identical string out.

`escapeHtml` handles `& < > " '` in a single `.replace(/[&<>"']/g, (ch) => MAP[ch])` so replacement
ordering cannot be gotten wrong. Every `${}` interpolation in the output is either `escapeHtml(x)`,
`String(someNumber)`, or a literal drawn from a closed union — with no exceptions, including inside
`<pre>` blocks. This matters concretely: `validLabel` at `src/protocol/publication.ts:72` permits any
non-whitespace non-control Unicode, so a hostile cache name or `nixSigKey` name can contain markup.
Scrubbing is not escaping; the page needs both.

Build the HTML as arrays of short strings joined with `"\n"`, following the precedent in
`src/operations/diagnostics.ts` (anchor: the `].join("\n")` in the writable-identity-mismatch banner).
`deno fmt` reflows long template literals; short joined strings survive formatting unchanged.

Document structure — seven sections, ordered as an operator's eye travels (*is it working?* → *how do
I use it?* → *what is it serving?* → *is it full?* → *is it publishing?*):

1. `<head>`: `<meta charset="utf-8">`, `<meta name="viewport" ...>`,
   `<meta http-equiv="refresh" content="10">`, and a `<title>` prefixed with the level when not ok
   (e.g. `DEGRADED · nixstr-cache`) so a background tab shows the state.
2. **Header** — product name, an uppercase level badge (`OK` / `DEGRADED` / `DOWN`), a one-line
   summary, the ISO timestamp, and the words "this page refreshes every 10 seconds".
3. **Reasons block** — rendered **only when non-empty**; its absence is itself the all-clear signal.
   Always humanized through `REASON_TEXT`.
4. **Use this cache** — a `<pre>` `/etc/nix/nix.conf` snippet using the **additive**
   `extra-substituters` / `extra-trusted-public-keys` forms so pasting cannot clobber
   `cache.nixos.org`, mechanically enforcing what `README.md:78-80` states in prose. Include the NixOS
   `nix.settings` equivalent. Reproduce the note from `README.md:96-98`: Nix still verifies every
   configured binary-cache signature; the Nostr signature authenticates the publisher and Hashtree
   root and does not replace Nix's own trust configuration. With zero keys, the keys line becomes a
   `# no cache keys known yet` comment.
5. **Caches** — a table of `# / name / root / keys / updated`, plus a `WRITABLE` marker. The primary
   label is the escaped `name` plus a truncated `pubkey`; render `safeIdentity`-style machine identity
   only as a secondary line. `safeIdentity` returns `"invalid"` above 136 characters
   (`src/operations/diagnostics.ts:216-217`) and a legitimate multibyte 64-byte name can exceed that,
   so `invalid` must never be a cache's only label. Append the overlay-entry count when non-zero.
   **Empty state** replaces the table entirely with: "No caches are selected. The daemon is running
   but has nothing to serve — check that `caches` is configured and that a relay is reachable."
6. **Storage** — a bar plus `ready / reserved / undeleted blobs`. The bar's only dynamic attribute is
   `style="width:N%"` with `N` an integer from `usedPercent`. Omit the section when
   `storage.available` is false.
7. **Writes** — signer line, uploads (PUT) accepted/refused, Blossom-server and publication-relay
   counts, batch progress, and staged totals. When writes are disabled this collapses to **one grey
   line**; emit no empty publication rows.
8. **Footer** — pointers to `/health` and `/nix-cache-info` as plain text, not links.

Degraded signalling without JavaScript uses three redundant channels and never colour alone: an
uppercase word in every badge (`OK` / `DEGRADED` / `DOWN` / `READY` / `BLOCKED` / `REPAIRING` /
`DISABLED`), a colour from a CSS custom property, and a coloured left border on non-ok sections.

CSS is a single `<style>` block sourced from a frozen module-level `const STYLE` string that is
**never interpolated** — roughly 60 lines. Include `color-scheme: light dark` and a
`@media (prefers-color-scheme: dark)` custom-property swap, a system font stack with no `@font-face`
and no `@import` (the CSP would block them anyway), `max-width: 64rem` centred, `user-select: all` on
`<pre>` so one click selects the whole snippet (the closest thing to a copy button without JS), and
one `@media (max-width: 40rem)` rule for narrow screens.

Emit no `href=` and no `src=` attributes anywhere. Emit no event-handler attributes. Emit no script
element.

## Risks

1. **The 503-rewrite wrapper** is the highest risk. Mitigated by `html()` having no status parameter,
   the catch path using 500, and the explicit wrapper-immunity test.
2. **Route drift.** If the `/` branch ever migrates below the empty-selection 503 gate, the page 503s
   exactly when it matters most and the wrapper converts it to a bare error line. The empty-selection
   test catches this.
3. **SQLite during shutdown.** Per-source `try`/`catch` in the daemon closure plus the outer catch in
   the route. Do not consolidate them.
4. **Query cost.** Each `GET /` runs a few aggregates and an `endpointWork()` scan. At one request per
   10 s per tab this is negligible, and the default bind is `127.0.0.1`
   (`src/config/config.ts:248`). If throttling is ever wanted, memoize `StatusInputs` for ~1 s in the
   *daemon closure*, keeping `createStatusSnapshotProvider` pure.
5. **Coordinator refactor scope.** Task 1c touches the write hot path. It is behavior-preserving and
   covered by `publication_loop_test.ts` and `publication_batch_test.ts`; if either regresses, land a
   private copy of the summarizer in `status.ts` and de-duplicate as a follow-up rather than changing
   emitted values.
