# Log compact reactive cache and write Hashtree state

## Goal

Expose the current read-cache roots and writable Hashtree candidate whenever
their authoritative reactive state changes, using canonical copyable `nhash`
identifiers and compact scalar fields instead of serialized publication,
manifest, inventory, or repository objects.

## Context

- `src/nostr/selection.ts` already deduplicates `selected$` snapshots and each
  `SelectedPublication.root.nhash` is the canonical value produced by strict
  nhash decoding.
- `HashtreeWriter.build()` already produces `HashtreeBuild.rootNhash`; the
  publication batch scheduler is the narrow boundary where a newly built root
  becomes the durable pending candidate.
- `src/operations/debug.ts` is the existing opt-in, compact one-line DEBUG
  facade. Keep this work separate from operational diagnostics and do not log
  full objects through `console.*` or JSON serialization.
- The worktree contains unrelated uncommitted debug/planning artifacts. Modify
  only the files listed above and preserve all unrelated changes.
